# Slick Slider 이슈와 대응 기록

2026-10-05 기준으로 현재 소스와 Git 이력을 대조했다. 아래 코드는 관련 부분의 발췌이며, 생략한 함수 문맥과 SCSS 중첩은 각 원본 파일에서 확인한다. **대응 코드가 존재하는 것과 최신 브라우저에서 재검증한 것은 구분한다.** 이번 작업에서는 문서만 수정했다.

## 1. 이미지 클릭 시 둥근 모서리가 직사각형으로 보임

**현상:** 기존 문서에 기록된 문제로, 이미지 클릭 시 둥근 모서리가 유지되지 않았다.

**대응:** 이미지뿐 아니라 Slick의 표시 창인 `.slick-list`, 내부 버튼에도 둥근 모서리를 적용했다. 표시 창의 `overflow`로 바깥 내용을 자른다. 현재 코드는 **1024px 이상**에서만 적용되며, transform과 WebKit 마스크 보정도 포함한다. 특정 브라우저의 버그가 원인이었다고 확정할 측정 자료는 이번에 확인하지 않았다.

위치: `src/scss/components/_gallery-responsive.scss`. 아래 규칙은 원본의 `@media (min-width: 1024px)` 내부 발췌다.

```scss
  /* 1. 슬라이드가 보여지는 '창(틀)' 자체를 둥글게 자르기 */
  .c-gallery__list .slick-list {
    border-radius: 1.25rem !important; //20px
    overflow: hidden !important;

    -webkit-transform: translate3d(0, 0, 0) !important;
    transform: translate3d(0, 0, 0) !important;
    -webkit-mask-image: -webkit-radial-gradient(white, black) !important;
  }

  /* 2. 버튼 투명화 및 둥글기 적용 */
  .c-gallery__list .c-gallery__open {
    border: none !important;
    background: transparent !important;
    border-radius: 1.25rem !important; //20px
  }

  /* 3. 내부 이미지 둥글기 적용 */
  .c-gallery__list .c-gallery__image {
    border-radius: 1.25rem !important; //20px
    display: block;
    width: 100%;
  }
```

## 2. 새로고침 직후 나머지 이미지가 함께 보임

**현상:** Slick이 초기화되기 전에는 원본 이미지 버튼들이 일반 문서 흐름에 나타날 수 있다.

**대응:** 초기화 클래스가 없는 동안 첫 버튼만 표시한다. Slick 초기화 후에는 이 규칙이 적용되지 않는다.

위치: `src/scss/components/_gallery.scss`의 `.c-gallery__list` 중첩 규칙을 펼친 코드.

```scss
.c-gallery .c-gallery__stage .c-gallery__list {
  &:not(.slick-initialized) {
    > .c-gallery__open:not(:first-child) {
      display: none;
    }
  }
}
```

**남은 제한:** Slick 로딩에 실패하면 이 초기 상태가 유지되어 나머지 이미지로 이동할 수 없다. 전체 갤러리의 대체 동작까지 구현된 것은 아니다.

## 3. Flex 내부에서 갤러리 너비가 과도하게 커짐

**원인과 영향:** Slick이 설정하는 트랙 너비와 Flex 항목의 자동 최소 너비가 결합하면 갤러리가 부모보다 넓어질 수 있다. 과거 `ad8a57e` 기록에도 이 문제가 남아 있다. 트랙 너비를 이미지 표시 너비로 간주하면 안 된다.

**대응:** 갤러리 Flex 항목에 `min-inline-size: 0`을 지정해 부모 레이아웃 안에서 줄어들 수 있게 했다.

위치: `src/scss/components/_product-layout.scss`.

```scss
.c-product__layout {
  .c-product__gallery {
    min-inline-size: 0;
    // 모바일 여백 처리 생략
  }
}
```

한 장씩 표시하는 현재 `src/js/main.js`의 설정은 다음과 같다. `variableWidth`, `centerMode`, `fade`, `vertical`은 명시적으로 켜지 않는다.

```js
$gallery.slick({
  slidesToShow: 1,
  slidesToScroll: 1,
  infinite: true,
  arrows: true,
  prevArrow: $('.c-gallery__control--prev'),
  nextArrow: $('.c-gallery__control--next'),
  dots: false,
  speed: 300,
});
```

설치된 `node_modules/slick-carousel/slick/slick.js`의 `setDimensions`에는 `variableWidth`를 사용할 때 트랙 너비를 `5000 * slideCount`로 설정하는 분기가 있다. 큰 트랙 자체가 오류라는 뜻은 아니지만, 이 상품 갤러리에 해당 옵션을 추가할 때는 레이아웃 계산을 다시 확인해야 한다.

## 4. 리사이즈 중 다음 이미지 일부가 보임

**현상:** 과거 `ad8a57e` 문서에는 Chrome에서 375→500px로 너비를 바꾸는 동안 다음 이미지가 노출된 측정 기록이 있다. 이 수치는 과거 기록이며 이번에 다시 측정하지 않았다.

**원인:** 설치된 Slick의 `resize`는 너비가 바뀌면 50ms 지연 후 위치를 계산한다. CSS 너비 변경과 슬라이드 재계산 사이에 차이가 생길 수 있다.

**대응:** resize 중 프레임당 한 번 `setPosition`을 호출한다. 초기화된 갤러리에만 호출하고, 이미 예약된 프레임이 있으면 중복 예약하지 않는다.

위치: `src/js/main.js`의 `initGallery`. Storybook의 `src/stories/scripts/gallery.js`에도 같은 대응이 있다.

```js
let resizeFrame = 0;
$(window).on('resize', () => {
  if (resizeFrame) return;
  resizeFrame = requestAnimationFrame(() => {
    resizeFrame = 0;
    if ($gallery.hasClass('slick-initialized')) $gallery.slick('setPosition');
  });
});
```

확인할 때는 리사이즈가 끝난 화면뿐 아니라 드래그 중 `.slick-list`와 활성 슬라이드의 실제 너비도 비교한다.

## 5. 무한 순환 복제 이미지가 라이트박스에 중복 집계됨

**현상:** `infinite: true`에서 생긴 복제 슬라이드까지 이미지 목록에 포함되어 라이트박스 순서·총 이미지 수·썸네일 대응이 어긋났다.

**원인:** 이전 코드는 버튼 자체의 `.slick-cloned`만 제외했다. 실제 복제 표시는 버튼의 조상 슬라이드에 붙을 수 있다.

수정 전 선택자 — `eb7cb59` 커밋에서 확인한 과거 코드:

```js
gallery.querySelectorAll('.c-gallery__open:not(.slick-cloned) img');
```

현재 대응 — `src/js/main.js`의 `initLightbox`:

```js
const images = Array.from(
  gallery.querySelectorAll('.c-gallery__open img'),
).filter((image) => !image.closest('.slick-cloned'));
```

현재 설치된 Slick의 `buildRows`는 `rows > 0`에서 래퍼를 생성한다. 과거 문서의 “기본 rows에서는 버튼 자체가 항상 슬라이드”라는 설명은 현재 소스에 적용하지 않는다. 슬라이드 판별에는 버튼 자체의 클래스만 확인하지 말고 `closest('.slick-slide')` 등 실제 조상 구조를 확인한다.

## 6. 기존 화살표의 위치와 화면별 표시가 어긋남

**원인:** `prevArrow`·`nextArrow`에 기존 jQuery 요소를 넘기는 경우, `appendArrows`만 바꾼다고 해당 요소가 자동 이동하지 않는다. 설치된 Slick의 `buildArrows`에서는 HTML 문자열로 만든 화살표에만 삽입 처리를 한다.

**대응:** HTML에서 갤러리 스테이지 안에 버튼을 배치하고 CSS로 기준 위치를 정했다. 모바일·태블릿은 화살표, 데스크톱은 썸네일을 제공한다.

위치: `src/pages/index.html`, `src/scss/components/_gallery.scss`. 아래는 중첩 선택자를 정리한 발췌다.

```scss
.c-gallery .c-gallery__stage {
  position: relative;

  .c-gallery__control {
    position: absolute;
    top: 50%;
    transform: translateY(-50%);
    display: grid;

    @include mq('desktop') {
      display: none;
    }
  }
  .c-gallery__control--prev { inset-inline-start: 1rem; }
  .c-gallery__control--next { inset-inline-end: 1rem; }
}
```

`840ca3c`에서는 갤러리 컨트롤의 화면별 표시를 CSS 미디어 쿼리로 옮겼다. Slick의 생성 DOM이나 인라인 스타일을 추측해서 덮어쓰기 전에 computed style과 실제 배치를 확인한다.

## 7. 슬라이드와 썸네일·현재 위치 안내가 따로 움직임

**대응:** 썸네일 클릭을 `slickGoTo`에 연결하고, 슬라이드 변경 이벤트에서 선택 표시와 접근성 상태를 함께 갱신한다.

위치: `src/js/main.js`의 `initGallery`.

```js
function syncThumbs(index) {
  $thumbs.each((i, thumb) => {
    const isCurrent = i === index;
    $(thumb).toggleClass('is-active', isCurrent);
    if (isCurrent) $(thumb).attr('aria-current', 'true');
    else $(thumb).removeAttr('aria-current');
  });
  $status.text(`Image ${index + 1} of ${$thumbs.length}`);
}

$gallery.on('beforeChange', (_event, _slick, _currentSlide, nextSlide) =>
  syncThumbs(nextSlide),
);
$thumbs.on('click', (event) => {
  const index = Number($(event.currentTarget).attr('data-index'));
  if (Number.isNaN(index)) return;
  $gallery.slick('slickGoTo', index);
});
```

**Storybook 보완:** `Gallery.stories.js`는 독립 전시를 위해 본문 썸네일을 제거한다. 이때 썸네일 개수로 총수를 계산하면 0이 된다. 전용 `src/stories/scripts/gallery.js`에서는 Slick의 실제 슬라이드 수를 사용한다.

```js
$status.text(
  `Image ${index + 1} of ${$gallery.slick('getSlick').slideCount}`,
);
```

## 8. 포커스 외곽선이 잘리거나 모바일에 실행 불가능한 조작이 남음

**외곽선 문제:** Slick의 클리핑과 이미지 버튼의 `overflow`가 바깥 포커스 표시를 자를 수 있다. `src/scss/components/_gallery.scss`에서는 이미지 버튼의 `:focus-visible`에 `outline-offset: -6px`을 지정해 안쪽에 표시한다.

**모바일 문제:** 라이트박스는 데스크톱 전용이므로 모바일에서는 이미지 버튼을 `disabled`로 만들고 대화상자를 여는 ARIA 속성도 제거한다. 화면 변경 시 포커스가 있었다면 다음 이미지 버튼으로 옮긴다.

**복제 슬라이드 대응:** `src/js/main.js`의 `syncImageControls`는 데스크톱 초기 동기화에서 표시 중인 원본 슬라이드만 Tab 순서에 포함하며 Slick 재초기화에서도 동기화한다.

```js
const slide = element.closest('.slick-slide');
element.tabIndex = slide
  ? (slide.classList.contains('slick-active') && !slide.classList.contains('slick-cloned') ? 0 : -1)
  : (element.contains(images[0]) ? 0 : -1);

// initLightbox 내부의 이벤트 등록
$(gallery).on('reInit', syncImageControls);
syncImageControls();
```

일반 슬라이드 전환 후에는 Slick 자체 접근성 처리도 동작하므로, 위 코드만으로 모든 전환의 Tab 순서를 보장하지 않는다. 래퍼 구조, 비표시·복제 슬라이드, 1023↔1024px 포커스를 실제 브라우저에서 확인한다. 자세한 내용은 Storybook의 ‘가이드/웹 접근성’을 참조한다.

## 9. 동작 줄이기 설정이 슬라이드에 반영되지 않음

운영 페이지의 `src/js/main.js`는 `speed: 300` 고정이다. Storybook 전용 `src/stories/scripts/gallery.js`에서는 초기화 시 설정을 반영한다.

```js
speed: window.matchMedia('(prefers-reduced-motion: reduce)').matches
  ? 0
  : 300,
```

운영 코드 반영과 실행 중 OS 설정 변경 감지는 미대응 상태다. Storybook 검증 결과를 운영 페이지의 대응 완료로 취급하지 않는다.

## 10. CDN과 Storybook의 로딩 경로가 다름

| 대상 | 현재 로딩 경로 |
| --- | --- |
| 운영 페이지 | `src/pages/index.html`에서 로컬 jQuery → Slick CDN → `main.js` 순으로 로딩. Slick CSS와 테마 CSS도 CDN 사용 |
| Storybook | `src/stories/helpers/gallery.js`에서 설치된 Slick JS를 `?raw`, CSS를 `?inline`으로 로딩 |
| 스토리 실행 | `helpers/frame.js`의 iframe에서 jQuery와 각 스크립트를 로딩하고 `initGallery` 다음에 `initLightbox` 실행 |

운영 `initGallery`에는 다음 가드가 있다. 메뉴 등 다른 기능에 초기화 오류가 전파되는 것을 막기 위한 처리이며, CDN 장애에도 갤러리 전체 기능을 사용할 수 있다는 의미는 아니다.

```js
if (typeof $.fn.slick !== 'function') return;
const $gallery = $('.c-gallery__list');
if (!$gallery.length) return;
```

운영 CDN URL에는 버전 지정이 없어 잠금 파일로 고정한 Storybook 로컬 버전과 일치한다고 보장할 수 없다. 표시 차이가 있다면 실제로 받은 JS·CSS, 화면 크기, 초기화 옵션부터 비교한다.
